# DeckRPG UI System Design

## Overview
A retained mode UI system with declarative composition API, designed for both game and application interfaces with optional world-space rendering capabilities.

## Core Architecture

### 1. Retained Mode Foundation
- **Persistent widget tree** with state management
- Widgets store properties, children, and event handlers in memory
- System automatically redraws when state changes (React/SwiftUI style)
- Event handling tracked and managed in the retained tree
- Efficient diffing for performance optimization

### 2. Engine Integration
- **Direct coupling** with engine systems (input, rendering, math types)
- Uses engine's Vector2/3, Color, Rectangle types directly
- Integrates with existing graphics pipeline and input handling
- No abstraction layers - prioritizing development speed over decoupling

### 3. Unified Game & App Interface
- **Single API** handles both game UIs and traditional application interfaces
- Flexible styling system supports:
  - Game aesthetics (futuristic, fantasy, retro pixel art)
  - Traditional app interfaces (clean, minimal, native-looking)
- Context-aware defaults for different interface types

### 4. Declarative Composition API
- **Declarative widget composition** with natural syntax
- **State-driven updates** - changing reactive values automatically updates UI
- **Progressive explicitness** - simple by default, explicit when needed
- Method chaining for natural, readable code

### 5. World-Space Rendering (Advanced Feature)
- Render UI elements to textures and place in 3D world
- Diegetic interfaces (sci-fi holographic displays, in-world screens)
- Same retained tree, different render pass with 3D projection
- Billboard and world-oriented modes

## API Design Philosophy

### Progressive Explicitness
The API supports multiple levels of control using the same underlying system:

**Level 1: Terse & Implicit**
```swift
Column {
    Text("Health: \(playerHealth)")
    Button("Heal") { heal() }
}
```

**Level 2: Semi-Explicit (More Control)**
```swift
Column()
    .spacing(15)
    .padding(.all, 20)
    .background(.gamePanel)
    .content {
        Text("Health: \(playerHealth)")
            .bind(playerHealthReactive) { health in "Health: \(health)" }
            .style(.healthText)
        
        Button("Heal")
            .onTap { heal() }
            .style(.primaryButton)
    }
```

**Level 3: Fully Explicit (Complete Control)**
```swift
Column()
    .layout(FlexLayout(direction: .column, justify: .start, align: .stretch))
    .style(Style()
        .withPadding(Spacing(all: 20))
        .withBackground(.gamePanel)
    )
    .content([
        Text()
            .text("Health: \(playerHealth)")
            .reactiveBinding(playerHealthReactive) { health in "Health: \(health)" }
            .style(TextStyle().withFont(.system(16)).withColor(.red)),
        
        Button()
            .title("Heal")
            .tapHandler { heal() }
            .style(ButtonStyle().withBackground(.blue))
    ])
```

### Smart Defaults System
- **Global defaults** for consistent theming across the application
- **Context-specific defaults** (inventory UI vs dialog UI vs game HUD)
- **Theme support** for easy switching between visual styles
- **Component-level defaults** for custom reusable components

```swift
// Global theme configuration
UI.setGlobalDefaults {
    Column.defaultSpacing = 12
    Text.defaultFont = .gameFont
    Button.defaultStyle = .gameButton
}

// Context-specific overrides
UI.pushContext("inventory") {
    Column.defaultSpacing = 2    // Tight spacing for inventory grids
    Text.defaultFont = .small    // Smaller text for item descriptions
}
```

## Core Component Names

### Layout Containers
- **Column** - Vertical stack layout
- **Row** - Horizontal stack layout  
- **Stack** - Overlapping/z-index layout (layered)
- **Grid** - Grid-based layout
- **Flow** - Flexible wrapping layout
- **Container** - Generic container with styling

### Content Elements
- **Text** - Text display (keep familiar)
- **Button** - Interactive button (keep familiar)
- **TextField** - Text input
- **Picker** - Dropdown/selector
- **Toggle** - Boolean switch
- **Slider** - Range input
- **Image** - Texture/icon display

### Layout Helpers
- **Spacer** - Flexible spacing element
- **Divider** - Visual separator line

## Layout System

### Flexible Layout Options
- **Flex-inspired** layout for responsive, flexible interfaces
- **Absolute positioning** for precise control (game HUDs, overlays)
- **Grid layout** for structured content (inventories, skill trees)
- **Flow layout** for wrapping content

### Layout Examples
```swift
// Flex-style responsive layout
Row()
    .distribution(.fillEqually)
    .alignment(.center)
    .spacing(10)

// Absolute positioning for game overlays
HealthBar()
    .positioned(.topLeft, offset: (20, 20))
    .worldSpace(position: Vector3(0, 2, 0))

// Grid layout for inventories
Grid(columns: 8, spacing: 2) {
    ForEach(items) { item in
        ItemSlot(item: item)
    }
}
```

## State Management

### Reactive Values
- **Reactive state containers** that automatically trigger UI updates
- **Explicit binding** for clear data flow
- **Computed properties** for derived state
- **Memory-safe** weak references to prevent retain cycles

```swift
// Reactive state
let playerHealth = Reactive(100)
let playerMana = Reactive(50)

// Automatic UI updates
Text()
    .bind(playerHealth) { health in "HP: \(health)" }

// Manual state updates trigger UI refresh
playerHealth.value = 80  // UI automatically updates
```

## Custom Components

### Reusable Component System
- **Component protocol** for creating custom, reusable UI elements
- **Full API access** - custom components use same features as built-ins
- **Composition-friendly** - components can contain other components
- **Library support** - build collections of themed components

```swift
struct HealthBar: UIComponent {
    let current: Reactive<Int>
    let max: Int
    
    func build() -> Element {
        Row {
            Rectangle()
                .fill(.darkRed)
                .frame(width: 200, height: 20)
                .overlay {
                    Rectangle()
                        .fill(.red)
                        .frame(width: 200 * (Float(current.value) / Float(max)), height: 20)
                        .alignment(.leading)
                }
            
            Text("\(current.value)/\(max)")
                .style(.healthNumbers)
        }
    }
}

// Usage - identical to built-in components
Column {
    HealthBar(current: playerHealth, max: 100)
        .style(.playerHealthBar)
        .onTap { showHealthDetails() }
}
```

## Example Use Cases

### Game HUD
```swift
struct GameHUD: UIComponent {
    let playerStats = Reactive(PlayerStats())
    let gameState = Reactive(GameState())
    
    func build() -> Element {
        Stack {
            // Top status bar
            Row {
                HealthBar(current: playerStats.value.health, max: 100)
                ManaBar(current: playerStats.value.mana, max: 100)
                
                Spacer()
                
                Text()
                    .bind(gameState) { "Score: \($0.score)" }
                    .style(.scoreDisplay)
            }
            .positioned(.top, offset: (0, 20))
            
            // Action buttons
            Row {
                ActionButton(icon: "sword", action: attack)
                ActionButton(icon: "shield", action: defend)  
                ActionButton(icon: "potion", action: usePotion)
            }
            .positioned(.bottom, offset: (0, -60))
        }
    }
}
```

### Settings Menu
```swift
struct SettingsMenu: UIComponent {
    let settings = Reactive(GameSettings())
    
    func build() -> Element {
        Column(spacing: 20) {
            Text("Game Settings")
                .style(.menuTitle)
            
            Column {
                Slider(
                    value: settings.value.volume,
                    range: 0...1,
                    label: "Volume"
                )
                
                Toggle(
                    isOn: settings.value.fullscreen,
                    label: "Fullscreen"
                )
                
                Picker(
                    selection: settings.value.difficulty,
                    options: Difficulty.allCases,
                    label: "Difficulty"
                )
            }
            
            Row {
                Button("Cancel") { closeSettings() }
                    .style(.secondaryButton)
                
                Button("Apply") { applySettings() }
                    .style(.primaryButton)
            }
        }
        .padding(40)
        .background(.settingsBackground)
        .cornerRadius(12)
    }
}
```

### World-Space Interface
```swift
struct HolographicDisplay: UIComponent {
    let data = Reactive(ShipData())
    
    func build() -> Element {
        Column {
            Text("SHIP STATUS")
                .style(.holographicTitle)
            
            Row {
                SystemStatus(system: data.value.engines, label: "ENGINES")
                SystemStatus(system: data.value.shields, label: "SHIELDS")
                SystemStatus(system: data.value.weapons, label: "WEAPONS")
            }
        }
        .style(.holographicPanel)
        .worldSpace(
            position: Vector3(2, 1.5, 0),
            billboardMode: .none,
            scale: 0.01
        )
    }
}
```

## Implementation Strategy

### Phase 1: Core Foundation
- Basic Element struct and retained tree
- Column, Row, Text, Button primitives
- Simple styling and layout system
- Reactive state and binding mechanism

### Phase 2: Enhanced Features
- Advanced layout options (grid, flex properties)
- Custom component system
- Animation and transition support
- Event handling improvements

### Phase 3: Advanced Capabilities
- Global defaults and theming system
- Context-specific configurations
- Performance optimizations (diffing, batching)
- Developer tools (UI inspector, layout debugger)

### Phase 4: World-Space Integration
- 3D texture rendering pipeline
- Billboard and world-oriented modes
- Integration with game world systems
- Diegetic interface examples

This system provides a solid foundation for all UI needs in DeckRPG while maintaining the flexibility to grow and adapt as requirements evolve.
